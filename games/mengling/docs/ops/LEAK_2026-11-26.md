# 线上站公开了不该公开的文件（2026-11-26 发现）

本文只写查到的事实和处置步骤，不含任何密钥内容。**第 1 步要用户在 Cloudflare 后台做，越早越好。**

## 事实

- 2026-11-26，主会话对线上站只发 HEAD 请求（没读内容）查到：`/.env.local` 返回 200、类型 `application/octet-stream`（不是首页兜底）；同站的 `d1_schema.sql`、`deploy.ps1`、`scripts/`、`docs/` 也能直接访问。
- 原因：`deploy.ps1` 以前在项目目录里直接跑 `wrangler pages deploy .`，整个目录都被上传。`.assetsignore` / `.wranglerignore` 里写了忽略，但没有起作用。
- `.env.local` 里是部署用的 Cloudflare 凭证（键名见 `deploy.ps1`）。能下载到它的人，就能用那个 token 做它被授权的事：至少能改这个 Pages 项目，是否还能动 D1 / Worker / DNS，要看 token 的权限，**未知**。
- 公开了多久：**未知**。`deploy.ps1` 从 2026-07-10 的首个提交起就是 `wrangler pages deploy .`，没有逐次的上传清单；本机 `.env.local` 的修改时间是 2026-10-16，更早有没有不知道。有没有人下载过：**未知**（要看 Cloudflare 的访问与审计日志）。
- Pages 的每次部署都有自己的预览网址，历史部署里的同名文件也能下载；只重新部署新版**不会**让旧部署消失。
- git 历史：`git log --all --oneline -- games/mengling/.env.local` 结果为 **0 条**；全仓任何路径的 `.env.local` / `.env` 也是 0 条，`.gitignore` 已忽略它。旧仓库 `mengling-idle` 从 2026-07-10 起的 108 个提交随导入在本仓历史里（到 `c75cd9c8`），同样 0 条。GitHub 上旧仓库的其他分支没查。
- 数据库里的用户密码是 PBKDF2 加盐哈希；登录令牌存在 D1 的 `sessions` 表。如果 token 有 D1 读权限，这两样要按「可能被读过」处理。
- 本轮没有访问线上站、没有部署、没有读 `.env.local` 的内容。
