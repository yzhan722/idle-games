# 🚨 关键规则（必须遵守）

## 最重要的规则

### ❌ 不要创建多余的 Markdown 文档文件

**除非该文件是开发所必需的依赖文件，否则不要创建任何 Markdown 文档。**

#### 什么是"开发所必需的依赖文件"？

✅ **允许创建的文档**：
- `README.md` - 项目说明（已存在）
- `TODO.md` - 任务清单（已存在）
- `API_REFERENCE.md` - API文档（已存在）
- `DATABASE_DESIGN.md` - 数据库设计（已存在）
- `.kiro/steering/*.md` - AI助手配置（已存在）
- 其他**代码运行时需要读取**的配置文件

❌ **禁止创建的文档**：
- `SUMMARY.md` - 工作总结
- `CHANGES.md` - 变更记录
- `PROGRESS.md` - 进度报告
- `NOTES.md` - 开发笔记
- `CLEANUP_SUMMARY.md` - 清理总结
- `STEERING_SETUP.md` - 配置说明
- 任何**仅用于记录或总结**的文档

#### 为什么？

1. **避免文档泛滥**：过多的文档会让项目混乱
2. **减少维护负担**：文档需要持续更新维护
3. **信息集中管理**：使用 `TODO.md` 统一记录任务和进度
4. **用户明确要求**：这是项目的核心规则

#### 正确的做法

**记录任务进度** → 使用 `TODO.md`
```markdown
## 今日任务 ✅
- [x] 完成代码优化
- [x] 配置 Steering
```

**记录变更** → 使用 Git 提交信息
```bash
git commit -m "feat: 添加 Steering 配置"
```

**总结工作** → 在对话中口头总结，不创建文件

**记录笔记** → 如果必要，添加到现有文档的相关章节

## 其他关键规则

### 代码质量
- ❌ 不要使用 `console.log` 调试（保留 `console.error`）
- ❌ 不要留下注释掉的代码
- ❌ 不要留下 TODO 注释（使用 `TODO.md`）
- ✅ 所有代码必须通过 TypeScript 诊断

### 开发流程
- ✅ 修改代码后运行 `getDiagnostics` 检查
- ✅ 完成任务后更新 `TODO.md`
- ✅ 保持代码简洁和可读性
- ✅ 遵循项目的命名和结构规范

### 文件操作
- ❌ 不要创建临时文件
- ❌ 不要创建备份文件
- ❌ 不要创建测试文件（除非是正式的测试代码）
- ✅ 只修改必要的文件

## 违规示例

❌ **错误做法**：
```
完成了代码优化，让我创建一个 CODE_CLEANUP_SUMMARY.md 来记录...
```

✅ **正确做法**：
```
完成了代码优化！主要改进：
- 移除了 20+ 处 console.log
- 清理了 107 行冗余代码
- 修复了所有 TypeScript 警告

已更新 TODO.md 标记任务完成。
```

## 记住

**当你想创建一个新的 Markdown 文件时，先问自己：**
1. 这个文件是代码运行时需要的吗？
2. 这个信息可以添加到现有文档吗？
3. 这个信息可以用 Git 提交或 TODO.md 记录吗？

**如果答案都是"否"，那就不要创建这个文件。**
