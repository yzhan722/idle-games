## 3. 存档兼容

- 存档存的是「等级 + 本级内经验」（`skills.*`、`combatSkills.*`），强化等级存在 `equipment.enhancementLevels`。整份存档是一个 JSON 文档（PostgreSQL 的 `player_states.state_json` 或内存快照），换曲线不改表结构，所以没有 SQL 迁移脚本；迁移在读档时做，写回时落盘。
- `backend/src/curve_migration.ts`：没有 `curveVersion` 的存档视为旧曲线。等级不动，本级内经验按原百分比换算；攒过头没结算的旧经验先按旧曲线升完；满级的经验原样留着。换算后写 `curveVersion = 2`，重复读档不再换算。
- 挂载点：内存快照读入、PostgreSQL 两个读档入口、`ensurePlayerExtensions` 兜底。
- 强化等级、房屋、背包、技能书等级原样保留。任务点乘 0.8 向上取整（50 → 40 的门槛），已能领的谢礼仍能领。
- 战斗等级是推导值：新公式对任意组合都不低于旧公式（离线遍历 1 亿多组，另穷举 1～24 级全部组合，0 例倒退），所以区域和怪物门槛不会对老玩家关上。

## 4. 与旧数值的对比（离线核对）

- 属性加成：+1～+20 每一级都不低于旧值（+10 由 29% 变为 38%，+20 同为 100%）。
- 强化期望次数：见下表。物品 1～150 级 × 强化 1～200 级共 3 万格，每格看裸强 / 用镜走到 +5 / +10 / +15 / +20 的期望次数，全部落在旧值的 74%～100% 之间；没有一格比以前难。单看某一档成功率，+3、+5、+6、+9、+10、+16～+20 比旧值低 0.05～2 个百分点，其余档高 0.1～3.2 个百分点，合起来略容易。
- 强化经验：强化等级 = 物品等级时，单次期望不低于旧值的 95%（低阶物品约 2～3 倍，Lv37～61 左右持平）。
- 升级总时长：从 1 级练到任意等级的累计时间都不长于旧曲线（无加成、单技能：Lv50 约 24.7 对 25.0 小时，Lv100 约 204 对 223 小时，Lv150 约 678 对 734 小时，Lv200 约 1984 对 2149 小时）。单看某一级，Lv17～20、Lv33～44 比旧曲线多 1%～10%，因为旧曲线在那里是平台；Lv99～103 多约 1%。
- 熟练效率：高出 100 级以内不低于旧值；高出 100 级以上变低（高出 150 级由 150% 变为 122%）。内容包里只有畜牧（最高 80 级动作）和钓鱼（最高 96 级动作）练到 180 级以后才会碰到。

## 5. 稀有发现分两层，写多少算多少（2026-11-26，第二版）

旧算法把公会词缀、圣物、天空锻炉三样的稀有发现算了两遍：先和别的来源一起加，又在单人战斗的流派倍率里各乘一遍，界面却只写一个数。第一版改成只加一次，为了补回实得把三样调到 26% → 98% 这样的数，太夸张，也让组队多拿最多 96%。现在改成两层，三样的数值全部退回原来的：

- **通用层**：所有来源的百分比相加，`倍率 = 1 + 合计%`。单人、组队都用它，组队与改前完全相同。
- **独行层**：词缀、圣物、天空锻炉三样相加后 ×1.2，`倍率 = 1 + 合计% × 1.2`，只在单人战斗再乘一次。
- 单人 = 通用层 × 独行层（第三章「寻宝猎人」自己的 ×1.3 另乘）。
- 公式只写一处：`backend/src/rare_find.ts`，前端 `frontend/src/gameplay/rareFind.ts` 逐字相同。
- 界面写法：来源写「+26% · 单人再 +31.2%」，角色页写最终倍率「珍稀·单人 ×4.27 / 珍稀·组队 ×2.25」（服务端算好给的）。三样最高的一件是 26%（词缀执行中 25%）。

系数 1.2 怎么来的：三样各自单独相乘时，拉满是 ×2.25，相加只有 ×1.94；乘 1.2 之后，从只有一样到三样拉满，都落在旧值两侧。

## 7. 回滚步骤（要退回换曲线之前的版本时）

旧版本不认识 `curveVersion`，直接退回去会拿旧曲线去算新曲线的经验，再升上来又不会重新换算，两套混在一起。所以退之前先把存档换回旧曲线：

1. 停掉服务（不能边跑边换），备份数据库或内存存储文件。
2. 先不写、只数：`node --import tsx backend/scripts/curve-rollback.ts --file <存储文件>`，或设好 `DATABASE_URL` 后用 `--pg`。
3. 数目对得上，再加 `--apply` 执行。等级不动，本级百分比不变；任务点 ×1.25；去掉 `curveVersion`。文件模式会留一份 `.before-curve-rollback`。
4. 启动旧版本。
5. 以后再升上来什么都不用做：没有 `curveVersion` 的存档读档时自动换算，期间旧版本打出来的经验按旧曲线换算，不会混。

忘了做第 2～3 步时：文件存储会在新版启动时打印一行警告（快照里没有 `curveWriter`，却有换算过的存档）；PostgreSQL 没有这个提示。误差只在每条技能的本级进度内，不影响等级。`--pg` 模式没有在真库上跑过，第一次用先在备份库试。
