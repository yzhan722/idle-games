# 战斗次级属性（`WL-G3`，2026-11-26 起生效）

命中、闪避、物抗、元抗。数值全部由自己的封闭公式给出。

- 公式只写一处：`backend/src/combat_secondary.ts`，前端 `frontend/src/gameplay/combatSecondary.ts` 是逐字相同的拷贝。
- 怪物数值由 `backend/src/monster_secondary.ts` 按「区域底子 + 体型」推出，写进内容包的怪物条目；战斗只读内容包。
- 守护：`backend/src/combat_secondary.test.ts`（公式性质、数据 = 公式、服务端战斗）、`scripts/combat-secondary-parity.test.ts`（两份文件逐字相同、面板 = 服务端、16 种怪 × 7 套配装预览与真实引擎逐血量一致）、`backend/src/combat_secondary_balance.test.ts`（11 个区域的新旧对比）。

## 规则

| 项 | 公式 | 说明 |
|---|---|---|
| 命中 | `100 + 10·等级` | 怪物用自己的等级；玩家用战斗等级，再加「攻击」技能每级 +2、装备、食物 |
| 闪避 | 只来自装备与食物（怪物来自区域与体型） | 没有底子，所以老存档不穿对应装备就和以前一样 |
| 落空率 | `0.6 · r / (r + 0.6)`，`r = 闪避 ÷ 命中` | r 很小时约等于 r；命中率封底 40%；对方没有闪避就必中（封顶 100%） |
| 落空怎么发生 | 不掷骰子。每挥一次，落空条加上落空率，满 1 次就落空一次；从半条开始 | 预览与服务端逐次一致，也没有运气好坏 |
| 抗性 | 伤害倍率 `1 − 0.7·抗性 / (|抗性| + 140)` | 每 10 点约 5%，越堆越慢，到不了 70%；负数是弱点 |
| 伤害类型 | 近战、远程是物理，魔法（法杖 / 权杖）是元素；怪物看 `damageType` | 打谁、被谁打，各吃对应的抗性 |
| 不受影响 | 主动技能必中；首领蓄力重击躲不掉；瘴气、喷发等按生命百分比的机制不吃抗性 | |
| 没有次级属性的对手 | 竞技场擂主、圣骑士幻影等没有这些字段：必中、无抗性 | 规则和以前一样 |

落空条存在 `hpCombat.playerMissMeter / enemyMissMeter`（可选字段）。旧存档打到一半的战斗没有这两个字段，按起始值处理；不改表结构，没有 SQL 迁移。

## 攻击速度

食物、药剂、套装上的 `combatSpeed` 点数折成攻击速度：每点 0.1%，全部来源合计封顶 3%，开战时定下，这一场不再变（`attackSpeedPct / attackSpeedInterval`）。界面写折算后的数。

## 组队副本（2026-11-26）

- 公式只写一处：`backend/src/party_combat.ts`，前端 `frontend/src/gameplay/partyCombat.ts` 除引用那一行外逐字相同。波次构成、小队数值、每一下伤害都在里面，演出与服务端裁判用同一份。
- 命中与抗性按期望值折进每一下：普攻 ×（1 − 落空率）× 抗性倍率；技能、首领秘技必中，只吃抗性。演出里不单独出现「落空」。自己用面板数值；队友命中按等级、没有闪避和抗性。组队专用的闪避率（`evasionPct`）、暴击率、暴击伤害照旧。
- 服务端不重打一遍，只判能不能结算（`backend/src/party_run.ts`）：
  - 逐波推进；刚结算过的那一波重发，返回上次结果、不再发奖；其余波次拒绝并告知该打第几波。
  - 早于最短可能时间（读条全满、技能全就绪、每下都暴击且打满、没有浪费）拒绝，第 2 波起再加 650 毫秒换波。
  - 长期速度：时间额度按真实时间攒，上限 30 秒，每清一波花掉期望用时的 60%。额度跟着人走：重开一场、换队伍、团灭重整都不重新给满。
  - 期望用时取开打时与报波时两支小队里快的那个，队友中途全退也不会突然要等很久。
  - 时钟往回拨：起点自动收回到现在，不会卡到时钟追上来。重开后这一波的起点不早于上一轮最后一次结算，所以上一场的迟到请求领不到东西。
  - 服务重启后陪练名册是空的，开战、清波、看队伍时按设备号认回来，等级与玩家看到的一致。
  - 技能次数只认出战的，按冷却与经过时间封顶；经过时间最多算期望用时的 4 倍（不少于 30 秒）。
  - 等级门槛与单人同一张表，取关卡里最低的一档；开战时查全部真人队员，领奖时再查本人。
  - 敌人与奖励按这一波开始时的人数，临领奖前拉人不多给。首领 2.2 倍，亲卫按小怪 0.75 倍（原来亲卫也按 2.2 倍、且和画面上不是同一只）；只有首领计首领击杀。
  - 拒绝只记数（`partyRun.rejects`）和写服务端日志，不动进度；客户端按 `retryAfterMs` 等一下重报同一波。
  - 客户端连着没结算成功：每 2 次向服务器重新对账（队伍、活动、该打第几波），连 6 次且页面开了 10 分钟以上就刷新整页（`partyRaidData.recoveryStep`）。
- 掉线：进度停在没打完的那一波，重连后从头打这一波；离线多久都只够结算这一波。团灭：`POST /party/wave-reset` 回第 1 波。换队长不影响进度；退队再进同一场，进度还在。

## 区域难度档位（`WL-G3`，单人，2026-11-26）

- 11 个战斗区域各有普通 / 困难 / 噩梦三档，按区域选，存在 `zoneTiers`；没选就是普通。公式只写一处：`backend/src/zone_tiers.ts`，前端 `frontend/src/gameplay/zoneTiers.ts` 逐字相同。
- 普通档原样返回内容包里的怪物，旧存档结算逐位不变（另与改动前的编译产物比过 83 只怪 × 3 套配置 × 20 分钟连打，连掉落在内 249 份存档摘要全部相同）。

| 参数（`ZONE_TIER_RULES`） | 困难 | 噩梦 | 说明 |
|---|---|---|---|
| 攻击 | ×1.3 | ×1.6 | 主要的难度 |
| 生命 | ×1.005 | ×1.01 | 一场只打几下、一下 3 秒，生命多一点就可能多打一下，每小时反而更少，所以只加一点点 |
| 闪避 | + 命中的 0.3% | + 0.6% | 同上 |
| 物抗、元抗 | +1 | +2 | 同上 |
| 经验 | ×1.25 | ×1.33 | |
| 掉率（稀有掉落与掉落表） | ×1.2 | ×1.3 | |
| 战败重生 | 75 秒 | 90 秒 | 普通 30 秒。没有它，「赢一场输一场」的角色在困难里死得更快、反而多拿 40%～60% |
| 开放条件 | 普通累计击败 100 只 | 困难累计击败 200 只 | 普通用现成的 `killsByMonster`（含组队），更高档记在 `stats.zoneTierKills` |

- 金币、防御、出手间隔、首领机制、掉落物都不变。竞技场、圣骑士试炼、组队副本不受影响。转生把选择收回普通，已开放的档位留着。
- 离线结算、连续战斗都按开打那一刻选的档位；中途改选，下一场起算。
- 怪物详情里的「连打」一行按现在的装备、技能、吃喝模拟连打一小时（`frontend/src/gameplay/farmPreview.ts`）：血量带到下一场、胜了歇 3 秒、败了按档位重生、连败 3 次停手，食物与魔力药按背包数量吃，吃出来的状态下一场起算；个人经验 / 金币倍率由 `GET /player/state` 的 `combatGains` 给。11 个区域 × 三档 × 4 套配置与真实结算逐场比对，胜场、败场、停手完全一致。不算：途中升级、掉落、药剂在同一场中途生效的攻防。

## 单人地下城（`WL-G3`，2026-11-27）

- 规则与参数只写一处：`backend/src/dungeon_rules.ts`，前端 `frontend/src/gameplay/dungeonRules.ts` 逐字相同；存档状态在 `backend/src/dungeon.ts`。入口在冒险页难度旁的「地下城」按钮，接口 `POST /combat/dungeon/start { zoneId, tier }`。
- 选一个打通过（首领至少击败过一次）的区域和已开放的档位，连打 5 波：该区域最强的 4 只普通怪按等级从低到高，末波是首领。每一波就是一场普通的单人战斗，经验、金币、掉落、精华照常结算（按波累加），档位按开地下城时选的。
- 波间歇 10 秒（连续战斗是 3 秒），生命不回满，只按脱战速度回一点；食物、饮品按配好的槽位照常吃。
- 全通：从这 5 波怪物已有的稀有掉落里按各自掉率加权抽 1 件作通关奖励（不加新物品、不加货币），弹一个小结算。
- 战败：按已过的波数结束，不重生、不续打，没有通关奖励。逃跑、换打别的怪、战斗被别的入口收掉，都按「离开」结束。
- 每天（东八区）3 次，开始时扣。离线：两次结算相隔超过 90 秒就按已过的波数结束（结在上次结算的时刻），空档里一场也不打。
- 旧存档没有 `dungeonRun / dungeonDaily`，结算与原来相同；状态在存档 JSON 里，不改表结构，两种存储走同一个结算入口。
