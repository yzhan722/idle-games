### 搬移规则（为什么行为没变）

- 只搬两类顶层语句：函数声明；初始化时没有副作用、也不读别的文件的 `const` / `let`（含 517 个 `document.getElementById('固定 id')`）。`__ARn_DEBUG__` 只是把一个全是函数的对象挂到 `window`，也搬了。
- 绑定事件、调用函数、读 `player` 的初始化，全部留在 `game.js` 原位，相互顺序没动。
- 会改写某个顶层 `let` 的函数和那个 `let` 必须在同一个文件（导入的绑定不能改写）。做不到的留在 `game.js`。
- 求值顺序：新文件都由 `game.js` 导入，先于 `game.js` 正文求值；它们求值时不读 `game.js`，所以互相循环导入不会碰到 TDZ。函数声明在链接阶段就可用，跨文件也一样。
- 早求值唯一可能的差别：原来靠 TDZ 报错走 `catch` 的写法（`getSafePolaroidAlbumCount` / `getSafePolaroidEntries` 读 `polaroidAlbum`）。`polaroidAlbum` 没搬，其余 `try` 块里没有搬走的绑定。
- 提前取的元素都在 `index.html` 里静态存在，不由 JS 生成，也不在会被整段重写的容器里。

之后加的 `save-core.js`（存档读写与相册裁剪，约 4.1 KB）不是搬出来的，是新的纯函数文件，不参与拼回；上下两张表没有重算，脚本实际是 17 个。

`node tests/split_check.mjs` 逐条检查上面这些，并把 57 块按 `[[split N]]` 拼回去，与搬移前的 SHA-256 比对（搬移之后的小修登记在 `tests/split_manifest.json` 的 `edits`，比对前先撤掉）。另外用 `tsc --checkJs` 对拆分前后各跑一遍：两边都是同样的 407 条（都是原有的 DOM 类型提示），没有新增「找不到名称」。

图片的 `?v=` 换号登记在 `assetVersions`（比对前先按文件还原），同一句改很多处的小修用 `count` 记次数。

以后继续改这些文件：要么把改动登记进 `edits`，要么把 `baseline` 改成 `null`（其余检查照常）。

### 版本号

`game.js` 与 11 个新文件互相引用，`?v=` 必须处处相同，否则浏览器会把 `game.js` 当成两份各跑一遍。改任何一个新文件：把所有 `?v=hd60` 一起加一（`public/*.js` 的 import、`index.html` 的 `modulepreload` 和最后两行脚本）。`static_check` 和 `split_check` 都会拦。没有 service worker。

#### 2026-11-27 核对：`vision.js` 升到 hd61、`game.js` 留在 hd60，会不会混

- 线上现在是拆分前的 `game.js?v=hd57` + `vision.js?v=hd31`。`hd60` 这组（拆分后的 12 个文件）、`vision.js?v=hd61`、`save-core.js?v=hd61` 都还没上线过。
- 线上响应头（`curl -I`，只看头）：`Cache-Control: public, max-age=0, must-revalidate` 加 `ETag`；仓库里没有 `public/_headers`，`wrangler.toml` 只配了 `[assets]`。浏览器每次打开都带 ETag 问一遍，没改的回 304。
- **服务器不看 `?v=`**：`vision.js?v=hd31` 和 `?v=hd61` 回同一个 ETag。所以 `?v=` 只防两件事：不守缓存规矩的 App 内置浏览器；同一页里同一个文件写成两个地址，被当成两个模块各跑一遍。
- 结论：这次不会混，也不会因为接口不对报错。
  - 新 `game.js` 只会从新地址 `vision.js?v=hd61` 拿 `vision.js`，这个地址以前没发过，任何缓存里都没有旧内容。
  - 反过来，缓存里留着旧的 hd57 `game.js`，它按旧地址 `vision.js?v=hd31` 去服务器，拿到的是新内容：新 `vision.js` 只加了成员（`bindPageLifecycle`、`isCameraLive`、`allowCameraResume` 等），旧 `game.js` 用到的 24 个成员都还在，照旧能跑（`tests/camera.test.mjs` 最后一条测试锁住）。
  - `modulepreload` 只下载、不执行，旧页面和新页面各预载各的，不会让同一份代码跑两遍。
- 选「不升 `game.js`」而不是「统一升号」：`game.js` 被 11 个拆出的文件反过来 import，升号要 12 个文件的 import 加 `index.html` 里的三处一起改，漏一处 `game.js` 就会跑两份（事件绑两次、存档写两份），比要防的问题更糟。hd60 没上线过，现在升号也换不来什么。

上线以后：

1. 改了 `game.js` 或 11 个拆出文件里任何一处：12 个文件的 `?v=` 一起加一。
2. 只被 `game.js` 引用的叶子文件（`vision.js`、`save-core.js`）：只升它自己的号，改 `game.js` 那一行 import 和 `index.html` 的 `modulepreload`，`game.js` 本身不用升。前提是叶子文件只增不删，旧 `game.js` 拿到新内容也能跑。
3. 被好几个文件引用的叶子（`audio.js`、`sprites.js`、`intimacy.js`）：所有引用它的地方一起改，否则会有两份实例（`static_check` 会拦）。

还剩的风险（不是这次引入的）：不守规矩的缓存留着旧 `index.html`，却去服务器拿 `game.js?v=hd57`，拿到的是拆分后的新 `game.js`，配旧页面可能起不来；`#boot-error` 只管下载失败，不管运行出错。正常浏览器每次都会重新确认 `index.html`，遇不到。要彻底防，得把页面和脚本放进带版本号的目录，等用户定。

## 首屏要下载什么

`node tests/first_screen.mjs [--root <游戏目录>] [--list]`：不开浏览器，从 HTML / CSS / JS 的加载写法推出「新存档进养成主界面之前必须下载」的清单。HTML / CSS / 脚本按 gzip 6 级算，图片按原样算；同一张图带不同 `?v=` 算两份（浏览器会下两遍）。画布贴图用假画布把新存档的房间跑一遍，问到哪张算哪张；窗景、季节按最大的一张算；窗台来猫、信箱有信按「有」算。

| 类别 | 改前 | 改后 |
|---|---|---|
| HTML | 28,970（1 个） | 29,351（1 个） |
| CSS | 55,584（1 个） | 55,983（1 个） |
| 脚本 | 390,997（17 个） | 394,680（18 个） |
| 图片 | 4,581,580（195 个地址） | 819,090（60 个地址） |
| 合计 | **5,057,131** | **1,299,104** |

- 改前比旧版本文档的 4.86 MB 多，主要是因为 12 张图在不同地方写了不同的 `?v=`，旧算法按文件只算一份，浏览器其实下两份。
- 纯下载量换算（不含握手、解析、解码）：10 Mbps 约 4.0 秒 → 1.0 秒，4 Mbps 约 10.1 秒 → 2.6 秒。**没有真机实测。**
- 首屏之后自动在后台补的：角色其余动作 23 张 1,207,968（一次两张、低优先级；浏览器开了省流量就不补，用到哪张下哪张）。
- 老存档：房间摆满时最多再多 29 张 398,176；水族馆主题的背景比默认的多 146,946。两样都占满约 1.84 MB，超过 1.5 MB。
- 开摄像头后才会再下 MediaPipe 和两个模型（见 `docs/THIRD_PARTY.md`），不算首屏。

### 图片怎么按需下

| 哪里 | 怎么做 |
|---|---|
| 画布贴图（`sprites.js`） | 一启动只下站立 4 帧和房间里固定摆着的 11 样；其余在绘制前问 `isReady()` 时才下。失败隔 1.5 / 3 / 6…30 秒再下，恢复联网立刻再下 |
| 打工、摘星 | `switchMode()` 里 `preloadModeSprites()`；没到之前怪物照旧画圆点兜底 |
| 角色动作帧没到 | 同一个动作（跑步缺帧）接着用手上那张，换了动作用站立帧，不再画蓝点；这时发饰按站立的头顶画 |
| 收起的面板（40 个，里面 212 处 `<img>`） | 这些面板收起时只是 `visibility: hidden`，`loading="lazy"` 拦不住；所以挂 `data-imgs-off`，样式把图平移到屏幕外很远（`translate`，占位不变），打开（去掉 `hidden`）立刻回位再下。第一次打开之后 `lazy-img.js` 去掉标记，并把这一面板看得到的图一次下齐 |
| 顶部胶囊、打工战报条 | 收起时是 `display: none`，`loading="lazy"` 就够 |
| JS 拼的面板内容 | `room-*.js`、手账页、打工技能条的模板都带 `loading="lazy"`（启动时会往收起的面板里写）；抽屉、三选一只在打开时才拼，不用 |
| 房间背景、窗景、季节 | 本来就按主题 / 时段 / 季节只下一张；加了失败重试 |
| 页面里的 `<img>` 失败 | `lazy-img.js`：1.5 / 4 / 10 秒各重试一次，恢复联网、切回前台时再试；`img { display: inline-block }` 保证失败时仍按样式的宽高占位 |

- 预载只留一张 `hero_idle`。
- 不支持 `translate` 属性的老浏览器（Chrome 104 以前、Safari 14.1 以前）：面板里的图照旧会提前下，只是省不到，功能不受影响。
- `tests/lazy_assets.test.mjs`：只下该下的、失败退避、后台补帧、没下完时所有绘制都不碰 `drawImage`、缺动作帧时用哪张、拼图底图失败会重来、每个 `<img>` 的样式都写死了宽高。

### 图片重采样

135 张按「最大显示边长的 2～3 倍」重采样（Lanczos、预乘透明，webp 质量 90～97、透明通道无损），文件名不变，`?v=` 统一到 hd60：2,431,472 → 1,092,074。逐张的新旧尺寸、字节、比对结果在 `docs/asset_resize.csv`。

- 没动：角色立绘 28 张、背景 2 张、窗景 4 张、会画进 270px 拼图底图或显示本来就大的 8 张（含一张字节相同的复用图）、算下来不算过大的 6 张、`mon_elite`（比对过不了）。
- 门槛：缩到显示尺寸（2 倍屏）后和原图比，浅底、深底都要 SSIM ≥ 0.985、均方根误差 ≤ 3 / 255、各通道均值差 ≤ 0.8；不过就加大一档，再不过就不换。实际最低 SSIM 0.9907。
- 字节相同的复用图（9 组）按同一尺寸换，换完仍然字节相同。
- 原图在 `C:\Project\_work\ar-survivor\assets_before_resize\public\assets\`，脚本 `resize_assets.py`（从备份读，重跑不会二次压缩）、联系表 `contact_sheet.png` / `contact_sheet_edges.png` 在上一级目录。

## 这次做的

- `index.html` 给 16 个脚本加了 `modulepreload`：原来要等 `game.js` 下完才知道还有哪些文件，现在一起下，省一趟往返。不支持的浏览器会忽略。
- 脚本数量变多，任何一个没下完游戏都不会启动。加了「没加载完整 / 重试」提示（`#boot-error`，沿用摄像头说明卡的样式），由脚本标签的 `onerror` 显示。

## 没做的，和理由（脚本部分）

| 想法 | 能省 | 为什么没做 |
|---|---|---|
| 打工模式进入时再加载 | 8 KB gzip | 独立出来的只有 704 行；主循环、伤害、掉落都在 `updateGameplay` 里和养成共用一个函数，`switchMode` 是同步调用，改成异步要动十几处调用方 |
| 跑酷进入时再加载 | 几乎没有 | 没有单独的跑酷代码块，只有一个 30 行的 HUD 函数 |
| 房间活动面板打开时再加载 | 约 152 KB gzip | 它们的 `syncXxxUI()` 在启动和每次切模式时都会被同步调用 |
| `debug-hooks.js` 只在验证时加载 | 14 KB gzip | 会改变 `window.__ARn_DEBUG__` 出现的时间，15 个验证脚本这次不能跑 |
