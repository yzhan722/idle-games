# 加载体积与性能（`MC-COM5`，2026-11-26）

只有构建与静态扫描数据，没有真机帧率（这几轮不许打开游戏）。数字是磁盘字节，gzip 为 `gzip -9`。

## 1. 首屏下载

首屏 = 打开网址 → 封面 → 备战大厅「出战」页完整显示。`node scripts/first_screen.mjs --list` 逐个文件列出来。

| 类别 | 改前 | 改后 | 改后传输 |
| :-- | --: | --: | --: |
| 图片 | 13,283,172（163 个） | 1,462,110（62 个） | 1,460,433 |
| JS（2 个） | 1,626,028 | 1,629,321 | 443,741 |
| CSS | 253,569 | 253,826 | 43,730 |
| HTML | 81,292 | 83,043 | 14,442 |
| 音频 / 字体 | 0 | 0 | 0 |
| **合计** | **15,244,061** | **3,428,300** | **1,962,346** |

- 改前传输 13,781,810，改后 1,962,346，少了 86%。
- 「改前图片」是上界：图标全写 `loading="eager"`，大厅一开就把天赋、工坊、皮肤等没打开的面板全渲染一遍，脚本按调用图算它们会下载哪些图。`index.html` 自己那 138 个 `<img>`（84 张、5.99 MB）是确定的。
- 「改后」按全新存档、大厅整页都算（折叠线以下的模式卡也算）。
- 音效与音乐是 Web Audio 实时合成，字体用系统自带，都不下载。

怎么降的：

1. **按需加载**：`index.html` 里除封面和大厅「出战」页常驻的图，113 个 `<img>` 都加了 `loading="lazy"`；脚本拼的图标（`SkillIcons.ts`、`main.ts`）统一走 `ART_LOADING`。战斗 HUD 的 `.hud-top` / `.hud-bottom` 初始就 `display: none`（开局脚本本来也会设成这样），否则封面底下的 HUD 图会先下载。封面的 `.title-crest-trio` 一直是 `display: none !important`，那 3 张 384×384 吉祥物图原来白下载。
2. **预取**（`src/ui/LazyArt.ts`）：封面出来后空闲时取大厅的图；进大厅后空闲时取主战役 HUD 与常见机关标签的图；同时 3 张、低优先级，省流量模式不取；取过的图留着引用，免得浏览器回收后用到时又问一趟服务器。各模式、工坊、天赋、皮肤页的图点开才下载。
3. **占位与重试**：图标宽高全在 `style.css` 写死（`assets.test.mjs` 会查），等图不跳布局；超过 0.22 秒没到的图给一块淡底色；失败按 0.8 / 2.5 / 8 秒重试三次，全失败换透明图加虚线框，断网恢复、切回前台后再来一轮；脚本跑起来之前就失败的图也补重试。
4. **小图**：排行榜头像、天赋底座、文字里的吉祥物改用 `race_*_sm.png`（116×116），大厅四个属性小图标改用 `meta_*_sm.png`（72×72），都由原图缩小得到。
5. **图片重采样**：见第 3 节。
6. 自检 chunk（`World3DSelfChecks-*.js`，151,650）玩家不下载（上一轮）。

自动化测试（`navigator.webdriver`）下图标全部立刻下载，`auto_playtest.py` 里「图都到了」的检查不用改；写死 256×256 的 14 处检查改成「方图且不小于 72」，`?v=35` 全部改成 `?v=36`（**没跑过**）。

## 3. 图片重采样

- 规则：取该图在所有用法里最大的 CSS 显示边长；≤ 70 px 的缩到 3 倍，更大的缩到 2 倍（手机上同一处更小，3 倍屏也够），最小 72。LANCZOS，PNG 同名重存、保留透明。
- 164 张 PNG：11,933,253 → 4,619,593。没动的 8 张：7 张 `race_*.png`（大厅展台显示 251 px，源图 384）、`gacha_machine.png`（显示 132 px，源图 256）。
- `title_splash_bg.jpg`：尺寸不动（1376×768），重编码质量 88、4:4:4、渐进式，957,260 → 356,576。
- `public/` 合计 14.3 MB → 6.5 MB。
- 比对：按显示尺寸 2 倍、深浅两种底算 PSNR，164 张最低 40.6 dB、中位 45.2 dB；封面 38.9 dB。挑最差的 8 张加 4 种类型共 12 张拼联系表看过，3 倍屏下看不出差别。
- 原图备份：`C:\Project\_work\mob-control-3d\assets_before_resize\`。
- 3D 贴图：仓库里没有图片贴图（全部 Canvas / DataTexture 运行时生成），没有要动的。

## 4. JS：`index-*.js` 里是什么（esbuild 压缩后字节，上一轮统计）

| 模块 | 字节 | 能不能拆 |
| :-- | --: | :-- |
| `World3D.ts` | 331,277 | 主战役与公共流程，进游戏就要 |
| `modes/*.ts`（10 个独立模式） | 224,374 | 没拆，见下 |
| `main.ts` | 207,955 | HUD 与全部面板，入口就绑事件 |
| `State.ts` | 192,968 | 存档与数值表，入口就要 |
| `levels/LevelData.ts` | 71,463 | 主战役和各模式的关卡生成器在同一个文件 |
| `SceneThemes.ts` + `HumanoidModels.ts` | 56,190 | 首屏大厅就要 |
| `SkillIcons.ts` | 17,685 | 首屏就要 |
| `SoundManager.ts` | 11,744 | 首屏就要 |
| `legal/*` | 7,367 | 只有 7 KB，点开要多等一次下载，不值 |

**「大厅先出、three.js 和战斗引擎后加载」这次没做**，原因：

1. `main.ts` 顶层就 `new World3DFull(...)`，后面 3,000 多行的按钮、HUD、面板直接用 `world`；开局还要 `startLevel()` 把当前关卡搭在封面后面，大厅背景、奖杯台、装修间都是 3D 画的。推迟引擎等于把大厅改成「先没有背景再长出来」，行为会变。
2. 十个模式是继承链，`loadLevel` / `update` 每次都会调到模式里的方法，缺一个就崩；改成后加载要先换成「控制器对象 + 世界接口」。
3. 封面是纯 HTML + CSS，脚本是 `type="module"`，本来就不等 JS 就能画出来；拆了也只省「进大厅」前的等待，约 60 KB gzip。

要做的话，顺序是：模式改控制器 → 开始按钮里 `await import()` 加转圈 → `LevelData.ts` 的 11 个 `generate*Level` 跟着搬。都要能打开游戏验证才动。

另外：后处理（`EffectComposer` / `UnrealBloomPass` / `OutputPass`）一直关着（`usePostProcessing` 全代码只被设成 `false`），但构造时照样建好，连它的着色器约 23 KB（gzip 约 6 KB）。删掉画面不变；因为是画质开关，没擅自删。

## 5. 运行期

查法：从 `update()` 出发按调用图走 119 个每帧方法，列出全部 `new`、数组 / 对象字面量、闭包；再查 `dispose`、只增不减的数组、`requestAnimationFrame`、监听器、定时器。

改了的（数值与画面不变）：

| 位置 | 原来 | 现在 |
| :-- | :-- | :-- |
| `simulateUnits` 巨偶弱点 | 大机偶战里每只波波每帧新建 1 个数组 + 2 个对象 | 模块级常量表 |
| `projectToScreen` | 每个标签每帧新建一个对象（26 处调用） | 复用一个结果对象，调用方都是取完就用 |
| `segmentsIntersect` | 每次判定新建一个闭包 | 模块级函数 |
| `update` 材质时间 | 每帧新建数组 | 直接两次 |
| 门横幅（8 处） | 每次打门都 `needsUpdate`，材质要重新算一遍着色器参数 | 贴图没变就不动；换贴图不再标记重编 |
| 危险门变色 | 每次打门新建 2 个 `Color` | 模块级常量 |
| 传送带贴图 | 每块地形一张 `CanvasTexture`，换关没释放 | `loadLevel` 里 `dispose` |
| 门横幅贴图缓存 | 按「样式 + 数字」只增不减，每张 512×256 | 换关时超过 48 张整批释放 |

看过、不用改的：

- `requestAnimationFrame`：主循环一条；数字滚动动画每个元素一条，重来会取消旧的。
- 监听器：`World3D` / `LegalModal` / `LazyArt` 的 window、document 监听只在启动时挂一次；面板按钮的监听跟着 `innerHTML` 重画一起丢。
- 数组：单位、粒子、冲击波、光柱、光束、网格格子都是定长池；其余 60 来个数组都在 `loadLevel` 里清空。
- 粒子、单位、标签没有每帧 `new THREE.*`。

知道但没动的：

- `loadLevel` 只释放几何体，不释放每关新建的材质。释放会让着色器程序引用归零、下一关重新编译卡一下；不释放时程序按键复用，数量有上限。要动得先把每关的材质改成共用。
- `spawnFloatingPopup` 每次都 `querySelectorAll` 现有飘字做避让，密集时有开销；要改得看真机。
- `getSiegeDamageMultiplier` 每次攻击都重算（含一次对象分配），可以按帧缓存，但要和升级、增益变化的时机对上。
- `renderMainMenu` 每次都重画全部四个面板（包括没打开的），图片已经不跟着下载，但 DOM 重建还在；改成只画当前面板要逐个面板核对，没做。
