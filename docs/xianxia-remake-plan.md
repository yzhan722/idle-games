## 1. 为什么不能在旧版上改

旧版 `games/xianxia` 有两处权利阻塞，改名换皮都解决不了：

- **代码**：整个游戏跑在 Kittens Game 引擎上，`license.txt` 不允许商用和衍生作品。自己写的 `js/cultivation.js`（26,358 行）也用 `dojo.declare` 继承引擎的类，有 524 行直接引用引擎的资源、建筑、科技等对象，不能单独拿走。
- **内容**：小说《凡人修仙传》的书名、主角名、门派、地名、功法、法宝都在用。境界顺序「炼气、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫、真仙、金仙」也与原作一致。

## 3. 核心创意（暂名《长明山》）

**一句话**：长夜降临，你是一座破败山门最后的守灯人，用灯火重新照亮九层山台，直到天亮。

与旧版和常见放置游戏的根本区别：成长来自**在山上布灯的位置**，而不是堆建筑数量和研究清单。

### 3.1 布灯

- 一座山的剖面图，九层山台，每层若干灯位。灯亮范围向相邻灯位递减。
- 三种基础火：晨火、青火、霜火。相邻不同火的光重叠会调出四种混色，各有不同效果。同样的灯，摆法不同产出就不同。
- 资源只有四种：灯油、星屑、悟、愿。不再增加。

### 3.2 弟子

- 共 12 名手写弟子，各有两种心性和偏好的光。站在合适的光里修行，自动产出并成长。
- 没有抽卡，按剧情和山台开放逐个加入。

### 3.3 长夜潮

- 定时来一阵黑潮，压暗外圈的灯。灯会变暗，不会丢失。
- 离线最多结算一次压暗，回来不会看到损失惨重。

### 3.4 境界与突破

- 七重境界：点灯、明窍、守夜、照山、通明、燃星、长明。
- 突破条件是用指定灯阵守完一夜，条件公开、结果确定，没有随机失败。

### 3.5 薪传与结局

- 每一代可以把灯传给下一代，从九条「灯誓」里选一条带走。灯誓改变规则（如「只用青火」「灯少一半但更亮」），不是加百分比。
- **第一结局**：九层山台全亮，天亮。**真结局**：九条灯誓各完成一代。真结局之后不再追加永久成长。

## 4. 内容上限（写死，防止再次失控）

四种资源、七重境界、九层山台、12 名弟子、九条灯誓、约 40 种灯具；界面最多四页（山门、弟子、灯谱、薪传）。要加一样，必须先删一样，并由用户同意。

## 5. 技术方案

- TypeScript + Vite，逻辑核心是不依赖界面的纯函数，同一份核心给游戏、离线结算和模拟器用。
- 从第一天就有无界面模拟器：一条命令跑完第一结局，输出各境界耗时。
- 单文件不超过 800 行，进检查脚本。
- 本地存档带版本号、校验和导入导出；第一版不做账号和联网。
- 依赖只用可商用许可，并自动检查。
- 目录暂定 `games/changming-mountain`，与旧版无任何引用。
